# Database

PostgreSQL 14+ (developed against 18). One database (`niss_monitor`), owned by the API server. Access goes through
EF Core 10 (`Npgsql.EntityFrameworkCore.PostgreSQL`) with the `EFCore.NamingConventions` snake_case convention.
Raw SQL is used in exactly three places (all parameterised): the idempotent event insert, the input-bucket upsert and the
retention batch deletes (`server/NISS.Infrastructure/Persistence/PostgresStores.cs`).

Conventions

* every timestamp is `timestamptz` and UTC (a value converter normalises `DateTimeOffset` to offset 0 before it reaches Npgsql);
* primary keys are `uuid` generated by the application - for event-derived rows the key is the agent's id
  (`AppSessionId`, `ProcessSessionId`, `EventId`) so replays are naturally idempotent;
* semi-structured data lives in `jsonb` columns (`event_ingestion.payload`, `agent_status.*_json`, `system_metrics.disks_json`,
  `configuration_policies.policy_json`, `devices.ip_addresses_json`);
* nothing that identifies typed characters, clipboard contents or file contents exists anywhere in the schema.

## Tables

### Identity and devices

| Table | Purpose | Important columns |
|---|---|---|
| `employees` | people whose PCs are monitored | `id`, `employee_code` (unique), `full_name`, `department`, `email`, `active` |
| `devices` | enrolled PCs | `id`, `device_id` (unique, `PC-024`, numbered by sequence `device_number_seq`), `hostname`, `employee_id` FK, `os`, `os_version`, `agent_version`, `status`, `last_seen`, `last_event_at`, `machine_guid` (unique when set), `machine_serial`, `manufacturer`, `model`, `secret_hash` (SHA-256 of the 32-byte secret), `secret_rotated_at`, `service_stopped_at`, `last_boot_at`, `local_offset_minutes`, `created_at`, `updated_at` |
| `device_users` | Windows accounts seen on a device, optionally mapped to an employee | `device_id` FK, `windows_username`, `employee_id`, `first_seen`, `last_seen`; unique `(device_id, windows_username)` |
| `enrollment_tokens` | one-time enrollment tokens (hash only) | `token_hash` (unique), `employee_code`, `bound_device_id`, `expires_at`, `used_at`, `used_by_device_id`, `note`, `created_by` |

`devices.status` is the computed health (`PENDING/ONLINE/WARNING/OFFLINE/SERVICE_STOPPED`) or the administrative state
(`DISABLED/REVOKED`). Device ids of event tables (`device_id` columns) are the `devices.id` uuid, not the `PC-024` text.

### Activity (projections)

| Table | Row is | Key / uniqueness | Written from |
|---|---|---|---|
| `user_sessions` | one interactive Windows logon | `id`; `login_at`, `logout_at`, `login_missing` (logout seen first) | `USER_LOGIN/LOGOUT` |
| `process_events` | one raw process start/stop | `id` = event id | `PROCESS_STARTED/STOPPED` |
| `process_sessions` | one process lifetime | `id` = `ProcessSessionId`; `started_at`, `ended_at`, `process_name`, `executable_path`, `command_line`, `sha256`, `baseline` | `PROCESS_STARTED/STOPPED` |
| `application_sessions` | one foreground session | `id` = `AppSessionId`; `process_name`, `executable_path`, `window_title`, `started_at`, `ended_at`, `duration_seconds`, `interaction_seconds`, `idle_seconds`, `end_reason`, `session_type='FOREGROUND'` | `APPLICATION_FOREGROUND/BACKGROUND` |
| `input_activity` | counters of one time bucket | unique `(device_id, timestamp)` (`timestamp` = bucket start); `keyboard_activity`, `mouse_activity`, `click_count`, `double_click_count`, `wheel_count`, `optional_cursor_x/y` | `MOUSE_ACTIVITY/KEYBOARD_ACTIVITY` (merge upsert: counters keep the maximum) |
| `idle_sessions` | a non-active period | `kind` = `IDLE` / `LOCKED` / `DISCONNECTED`; `started_at`, `ended_at`, `duration_seconds` | `IDLE_*`, `SESSION_LOCK/UNLOCK`, `SESSION_CONNECT/DISCONNECT` |
| `system_metrics` | one metric sample | `id` = event id; cpu, memory, disk (first/`C:` disk), network, battery, uptime | `SYSTEM_METRIC` |
| `usb_events`, `file_events` | USB connect/disconnect, file metadata | `id` = event id | `USB_*`, `FILE_*` |
| `screenshots` | one stored screen capture (the JPEG itself is a file on disk; this row is the index) | `id`; unique `(device_id, frame_id)`; `captured_at_utc`, `session_user`, `employee_id`, `monitor_index`, `width`, `height`, `byte_size`, `rel_path`, `trigger` (`PERIODIC`/`FLAGGED`), `flag_term`, `matched_on` (`TITLE`/`PROCESS`), `clip_id`, `clip_seq`, `clip_total` | `POST /devices/screenshots` (not the event pipeline) |

### Health and live state

| Table | Purpose |
|---|---|
| `heartbeats` | one row per received heartbeat (server time, agent version, queue depth, clock offset, cpu/memory) |
| `agent_status` | **the live state row, one per device**: presence, user, foreground app + window, `open_applications_json`, idle seconds, interacting flag, cpu/ram/network, `session_agents_json`, `collectors_json`, queue depth, dead letters, last upload/error, `clock_offset_ms`, `live_updated_at` (newest information folded in; older backlog events cannot overwrite it) |
| `security_events` | health / security events (`kind`, `severity` INFO/WARNING/CRITICAL, `message`, `raised_at`, `resolved_at`) |
| `event_ingestion` | **every accepted event**: `event_id` (primary key = idempotency key), device, employee, type, effective `timestamp`, `received_at`, `sequence`, `source`, `schema_version`, `clock_offset_ms`, `local_offset_minutes`, `subject` (e.g. process name), raw `payload` jsonb |

### Administration

| Table | Purpose |
|---|---|
| `admin_users` | dashboard accounts (`password_hash` = ASP.NET Core Identity PBKDF2 hash, `role`, `enabled`, `last_login_at`) |
| `refresh_tokens` | rotating refresh tokens (hash only, `expires_at`, `revoked_at`, `replaced_by_id`) |
| `audit_logs` | admin actions (`timestamp`, `username`, `action`, `target`, `detail`, `ip_address`) |
| `configuration_policies` | monitoring policies; `scope` GLOBAL/DEPARTMENT/DEVICE + `scope_value`, `policy_json`; unique `(scope, scope_value)` |
| `app_category_rules` | wildcard patterns (`chrome*`) -> category, evaluated by priority then pattern length |
| `server_settings` | key/value: `retention`, `health_thresholds`, `policy_version`, `jwt_signing_key` (generated once when not configured) |

### Relationships

```
employees 1---* devices 1---* device_users
                   |
                   +---1 agent_status
                   +---* heartbeats, security_events, event_ingestion
                   +---* user_sessions, idle_sessions, application_sessions, process_sessions, process_events
                   +---* input_activity, system_metrics, usb_events, file_events
admin_users 1---* refresh_tokens          (audit_logs.admin_user_id / enrollment_tokens.bound_device_id are soft references)
```

Every table with a `device_id` foreign key cascades on device deletion. `employee_id` columns on the high-volume tables are plain
indexed uuid columns (no foreign key) to keep inserts cheap.

## Indexes

Every event table has `(device_id, <time column>)` and `(<time column>)` (the second one serves retention deletes and cross-device
reports). Additional: `event_ingestion (device_id, event_type, timestamp)` and `(employee_id, timestamp)`;
`application_sessions (employee_id, started_at)` and `(process_name)`; partial indexes for open rows
(`ended_at IS NULL` / `logout_at IS NULL` / `resolved_at IS NULL`); unique `input_activity (device_id, timestamp)`;
unique `devices (device_id)`, `devices (machine_guid) WHERE machine_guid IS NOT NULL`, `enrollment_tokens (token_hash)`,
`refresh_tokens (token_hash)`; `screenshots (device_id, trigger, captured_at_utc)` for the filtered timeline and the
split retention pass, and `screenshots (clip_id, clip_seq)` to read one clip's frames in order.

## Idempotency and ordering

`POST /events/batch` processes a batch in ascending `sequence` inside one transaction. Each event is inserted with
`INSERT ... ON CONFLICT (event_id) DO NOTHING`; a conflict means DUPLICATE and no projection runs. Ingestion for one device is
serialised with `pg_advisory_xact_lock`. Each event is wrapped in a savepoint so an event that cannot be projected is rejected on its own.
Projections tolerate late events (BACKGROUND before FOREGROUND, LOGOUT before LOGIN, IDLE_ENDED without IDLE_STARTED, stale
presence/foreground updates are ignored).

## Retention

`Retention` settings (days, `0` = keep forever; editable at runtime under `/settings/retention`). The `RetentionWorker` runs daily
(03:00 server time by default, `Workers:RetentionHourLocal`) and deletes in batches of 5000 (`ctid`-based, so no long locks):

| Setting | Tables |
|---|---|
| `RawEventsDays` (90) | `event_ingestion`, `process_events`, `input_activity`, `idle_sessions`, `file_events`, `usb_events` |
| `ApplicationSummariesDays` (365) | `application_sessions`, `process_sessions` (finished ones), `user_sessions` (finished ones) |
| `DeviceHealthDays` (180) | `system_metrics`, `heartbeats`, `security_events` (resolved ones) |
| `AuditLogsDays` (365) | `audit_logs` |
| `ScreenshotDays` (14) | `screenshots` where `trigger <> 'FLAGGED'` - **deletes the JPEG files too** |
| `FlaggedScreenshotDays` (90) | `screenshots` where `trigger = 'FLAGGED'` - flagged captures and clips, kept longer because they are the evidence |

Screenshots are the one exception to the batched `ctid` delete: rows and their files are removed together through
`IScreenshotStore` (a raw `ExecuteDelete` would orphan the images on disk). The two screenshot values fall back to
`ScreenshotStorage:RetentionDays` / `FlaggedRetentionDays` in `serversettings.json` when unset. See
[screen-monitoring.md](screen-monitoring.md).

Expired refresh tokens (7 days after expiry) are always removed; the `EnrollmentTokenCleanupWorker` removes tokens that expired more
than 7 days ago or were used more than 30 days ago.

## Migrations

EF Core migrations live in `server/NISS.Infrastructure/Persistence/Migrations`. `dotnet-ef` is a local tool
(`dotnet-tools.json` at the repository root): run `dotnet tool restore` once.

```powershell
# create a migration (from the repository root)
dotnet tool run dotnet-ef migrations add <Name> -p server/NISS.Infrastructure -s server/NISS.Api -o Persistence/Migrations

# apply to the database in Database:ConnectionString and exit
dotnet run --project server/NISS.Api -- --migrate
#   (or set Database:ApplyMigrationsOnStartup=true and start the server: pending migrations are applied at startup)

# regenerate the SQL script for DBAs (idempotent: safe to run repeatedly)
dotnet tool run dotnet-ef migrations script --idempotent -p server/NISS.Infrastructure -s server/NISS.Api -o deployment/database/schema.sql
```

`dotnet ef` uses the design-time factory in `Persistence/DesignTimeDbContextFactory.cs`; set `NISS_Database__ConnectionString`
to target another database.
